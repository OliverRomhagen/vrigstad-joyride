Complete Blender vehicle fleet

Select the parked Torget car with ?vehicle=volvo240, saab900, xc70, xc70-police, impala1970, micra-k11 or duett-epa. Start and use the normal movement/E controls. The HUD uses the model name. Without a query, parked cars and traffic pick a model for their type from VEHICLE_VARIANTS: a Volvo is a Volvo 240 or an Impala, a Saab a Saab 900, XC70 or Micra, an EPA a Duett and police a police XC70. The pick uses its own seeded stream, so the original traffic distribution and the rest of the world's rolls are unchanged. The tractor stays procedural. Unknown IDs use the default Volvo 240 at Torget. Models do not define dynamics: mappings reuse Volvo/Saab/passenger-car, police and EPA simulation. They are not calibrated real-world handling specifications. No experimental drivetrain is included.

Registry and lifecycle

src/game/render/vehicle-registry.ts declares stable IDs, names, paths, archetypes, wheel radius/base and default archetype mappings. Register a new model there and provide its GLB under src/public/media/vehicles. All exports use metres, +Y up, -Z forward and the shared body/wheel node names. Immutable provenance lives below. npm test checks all real files through Three's GLTFLoader and validates wheel locations and plausible bounds.

VehicleVisuals owns rendering state independently from simulation. Call attach(car,id,fallback,color) after adding a car, sync(car) after positioning it, update(focus,dt) once per frame and dispose(car) on removal. addCar accepts an optional sixth asset-ID argument overriding the variant pick. Names and short Swedish spoken names are read through vehicleVisuals.definition(car); they are not stored on simulation car objects. No new input or physics rules are introduced.

Loading is lazy inside the 120 m/8 desktop or 3 coarse-device detail budget. Templates and geometry/materials are cached and shared; instance transforms are cloned. Civilian bodies receive the same single seeded colour choice as their procedural fallback after asynchronous loading; police livery is preserved. paint(car,color) clones only that instance's civilian body materials; police livery is protected. Owned material clones are disposed with the visual; shared cached resources live for the page. Failures are reported as failed, retain the procedural fallback and never pretend the detailed asset loaded. Failed instances do not occupy detail slots. Removed cars ignore pending asynchronous work.

Wheel travel derives from rendered movement, using -Z forward and metre units; front steering derives from heading/distance and verified wheelbase. Teleports larger than 20 m do not spin wheels. Police beacons use existing emissive meshes; no point lights/shadows are added for them. Coarse detailed meshes do not cast additional shadows. The read-only game hook exposes the selected car's actual loading/fallback/detail and wheel state for tests.

Compression

gltfpack is pinned to 1.3.0 in the dev dependencies. The runtime uses the MeshoptDecoder already shipped with Three.js; no new runtime package is needed. Prepare a separate directory containing the original pinned exports under the filenames below, then run:

npm ci
npm run compress:vehicles -- /path/to/original-exports
npm test
npm run build

The script runs gltfpack -c -kn -km -noq for each public GLB: meshopt compression, retained named nodes/materials, no mesh simplification or vertex quantization. Always start from the originals, never an already compressed derivative. The loader and both Vitest asset/controller loaders configure MeshoptDecoder explicitly. Normal startup keeps the procedural fallback if decoding fails.

Generated primitive mesh names may change; authored nodes and material names are retained. This is geometric verification, not human silhouette/livery approval.

Uniform inherited wheel scales are supported; bake nonuniform ancestor scales in Blender before export. No model-specific collision changes are made.

Delivery and checks

Vite copies the only tracked GLBs from src/public to dist/media/vehicles. Relative URLs work under a GitHub Pages project/preview prefix. #167 has landed: the built HTML files are no longer tracked, and E2E serves dist directly. The fleet's Pages workflow publishes root teaser media followed by the entire dist tree, so production and preview both ship the Vite public assets. There is no root GLB compatibility copy, second tracked model directory or root HTML.

Run npm run check, npm test, npm run build, npm run test:e2e. The production build, actual asset parsing, gameplay/fallback and WebGL checks are automated; images are review artifacts, never pixel-diff tests. The upstream preview workflow requires a branch in the upstream repository. Optional manual CI dispatch is carried in a separate branch above the fleet feature; its base contains the feature tests. Vehicle checks now run through the ordinary Vitest unit workflow; there is no separate test:vehicles runner. Source parsing and visual-controller regressions run in Vitest; E2E keeps game load/enter/drive coverage and failed-asset fallback, without patching game source. The existing assertions have been migrated to tests/unit/vehicles/ after #164. The controller is a class, following the current lifecycle-owner convention.

Visual verification limits

Visible model attribution and media/vehicles/NOTICE.txt accompany the production and preview assets.

Geometric parsing is not reference approval. Round 2 retains the existing Saab silhouette comparison against an uncertain brochure proxy (recorded IoU ~0.9154), protected Volvo arch checks and shared XC70 export/pose checks. Impala and Micra sources retain their source-specific reference/refinement evidence but explicitly say human approval is pending. Duett final-pass measurements use wheel-anchored photographs and perspective estimates, not a completed full silhouette IoU or factory surface accuracy. All original reference registers/review reports remain available in the pinned trees. This integration makes no new real-world visual approval claim. Physical mobile/Safari performance, final silhouette/livery approval and traffic placement decisions remain for human review.

Collision envelopes remain those of existing archetypes, not model-specific body geometry. Large models can therefore visually overhang their collision shape. Physics/collision calibration is a separate gameplay decision.
